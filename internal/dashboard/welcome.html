Welcome to MaaS

Connect compatible AI clients to a MaaS API using the endpoint, key, and model identifiers supplied by your service provider.

Try the APIClient setup

What you need

Your MaaS provider supplies the connection details. The exact models and API features depend on that service.

Connection details

  • API base URL
  • API key
  • Exact model identifier
  • Supported API format, such as Chat Completions, Responses, or Messages

Keep credentials private

Store keys in a secret manager or a protected environment variable. Do not commit a real key to source control, paste it into shared examples, or include it in a request body.

Make a test request

This example uses an OpenAI-compatible Chat Completions endpoint. Use the API format documented by your MaaS provider.

Chat Completions

Replace the sample base URL and model identifier with the values for your service.

export MAAS_BASE_URL="{{GATEWAY_URL}}/v1"
export MAAS_API_KEY="your-api-key"
export MAAS_MODEL="provider/model-id"

curl "$MAAS_BASE_URL/chat/completions" \
  -H "Authorization: Bearer $MAAS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"'"$MAAS_MODEL"'","messages":[{"role":"user","content":"Reply with exactly OK."}]}'

If your provider uses a different authentication header or API dialect, follow its instructions instead of copying this request unchanged.

Find a supported model

Some MaaS services provide a model catalog; others require you to use a model identifier supplied by an administrator.

Optional model discovery

If your service exposes /models, you can try:

curl "$MAAS_BASE_URL/models" \
  -H "Authorization: Bearer $MAAS_API_KEY"

Use exact identifiers

Model names are service-specific. Copy the exact identifier from the service documentation or catalog; a friendly display name may not be accepted by the API.

Connect a client

Client settings vary by version and by the API formats your MaaS service supports. Keep the base URL and key consistent, and choose a compatible model and API format.

Claude Code

For an Anthropic-compatible MaaS endpoint, configure the client with the base URL and key provided by your service, then select a supported model.

export ANTHROPIC_BASE_URL="https://your-maas-host.example"
export ANTHROPIC_API_KEY="$MAAS_API_KEY"

Codex

Configure a custom model provider using the base URL, authentication variable, and API format supported by your service. For example, a Responses-compatible provider may use:

[model_providers.maas]
name = "MaaS"
base_url = "https://your-maas-host.example/v1"
env_key = "MAAS_API_KEY"
wire_api = "responses"

OpenCode

Add a provider with your MaaS base URL and an environment-variable reference for the key. OpenCode configuration schemas differ by version; use the schema for your installed version and pin an exact supported model identifier.

Pi

Add a provider using the base URL, API format, and model identifier supported by your service. Keep the API key in Pi’s supported authentication mechanism rather than in a shared model configuration.

These are general patterns, not provider-specific guarantees. Check your service and client documentation for supported endpoints, settings, and model capabilities.
